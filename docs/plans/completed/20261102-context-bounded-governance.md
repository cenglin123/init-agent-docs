# 有界上下文初始化与项目治理闭环

## 授权与目标

本计划定义 init-agent-docs 的分阶段初始化 Skill、检查工具与项目治理闭环。Agent 负责语义判断、任务分解、协作安排、提示词和模型选择；脚本负责确定性顺序、记账、路由、验收与止损。执行保持既有授权、预算与副作用边界。

交付目标是可恢复的初始化流程、可运行的检查与修复，以及 Skill 自身和生成项目可共同采用的轻量治理闭环。

## 已核实的基线

- 源码工作树开始时干净，当前为 main；主对话已 fetch 并核实与 upstream 的 ahead/behind 为 0/0。
- SKILL.md 为 931 行、84,486 字节；一次性调用并不消除执行期间的上下文成本。
- 根目录未见 AGENTS.md；维护规范在 README.md，生成项目规则在模板，执行指令集中在 SKILL.md。
- SKILL.md 关于 docs 文件治理规则的归属互相冲突；Small 不建 STRUCTURE.md，模板仍指向其中规则。第 9 步还无条件要求更新 STRUCTURE，并给出会解析成 docs/docs/audit-checklist.md 的相对链接。
- check_all.py 把合法 MEMORY.md 超过 14 天未改视作失败；AGENTS.md 缺失/解码失败被计为 0 行，行数检查误通过。
- 现有 test_skill_guidance.py 多处将短语和步骤标题固定在 SKILL.md，必须随按需披露调整为检查委托关系及行为合同，不能靠保留重复文字维持通过。
- 初始测试收集存在 `tests` 包导入冲突；该问题已修复，最终默认命令结果记于完成记录。
- 早期探索轨迹仅作为回顾线索与案例选择依据；没有旧新受控对照，不据此证明质量或成本的因果收益。

## 不变量与非目标

1. 保留可执行事实源优先、先读旧 instruction 再整合、无静默丢失硬约束、规范态正文、脚本派生索引、计划交接与独立验收。
2. Git/no-Git 与规模是独立轴；no-Git 不运行 Git、不自动 init、不生成 Git-only 资产。已有用户授权可直接作为 profile 和可选项的决策依据，不能因模板流程重复索要同一批准。
3. 普通代码项目仍用 scripts/maintain.py 与 .agents/memory/；仅 KB 叠加项目的交付件沿用 .meta/scripts/ 与 .meta/memory/，其文档维护器改名 docs_maintain.py 并委托 KB memory_index.py，不产生第二索引写入者。
4. 生成项目不必安装或引用 converge、init-kb-harness、embedding、API 或常驻服务。已选控制器时复用其质量流程；未选控制器时用项目本地合同与独立检查完成交付，不创立平行控制器。
5. 自维护不获得改规则的权限；自进化不能同轮改自己的通过标准后自证成功。既有授权持续有效，权限扩大需要对应授权。
6. 不自动修改 cc-switch 管理的宿主副本；只改已核实的来源。发布/部署作为单独交付边界记录，不把源码测试通过视作已部署。
7. 不将知识库领域专用的检索、隐私分类、主从设备、作者分离等机制复制到代码项目；本次不改 init-kb-harness 来源、不重构 worktree runtime、不造通用升级服务或新的 Agent 调度器。

## 架构与单源归属

### 执行入口与按需披露

- SKILL.md：保留发现信息、路径约定、核心不变量、profile 摘要、阶段路由、恢复方式和完成判据。目标不超过 200 行且不超过 24 KiB；这是本次交付预算，不声称对应固定 token，也不是模型能力上限。
- assets/references/initialization.md：唯一的初始化详细操作说明，按“调查与选项 / 最小入口与迁移 / 扩展资产 / 验收与交付”分区；入口明确只读取当前阶段的对应段，不要求全文预读。
- assets/references/design-principles.md：压缩后的设计依据，仅在发生取舍、维护原则或审查设计时读取；保留有行为影响的边界，不将原 931 行机械搬家。原 SKILL 的反模式段按“改变执行决策的判据并入对应操作参考、仅解释性且仍必要的内容归本文件、重复或无行为增益的内容删除”逐项登记迁移去向，不另建完整反模式注册表。
- assets/references/optional-integrations.md：仅在安装 hooks、会话级提醒或 worktree 时读取对应节，默认不加载。现有 workflow-patterns.md 保持协作与 worktree 契约的唯一详细来源，安装说明引用它，不复制 CLI 手册。
- assets/references/governance-contract.md：自维护、自治理、提案式进化的通用合同源；使用与 Git、规模、特定目录无关的中性表述，须可脱离本 Skill 和 KB 使用，不链接源码内部资产。自身 AGENTS 指向它；生成 Medium/Large 项目复制为 docs/governance.md，并同时生成 AGENTS 导航指针和 STRUCTURE 中的 governance.md 相对索引行；Small 从该合同提取最小闭环内联到 AGENTS，避免强制增加治理目录。项目具体路径和维护命令由 AGENTS 绑定，通用合同不假定 plans、memory、bugfix 或评测账本存在。若实现中确需 Git 专用段，必须采用既有 profile 条件块并在生成时投影，不能原样复制到 no-Git 产物。

文件数量是职责划分的结果，不要求拆出全部候选文件；实现者可合并相邻、实际很短的专题，但须保持同一事实只有一处可编辑源、条件分支可独立加载。对应功能指令字节比较固定为：旧侧 SKILL.md 84,486 B + assets/references/workflow-patterns.md 16,551 B = 101,037 B；新侧为 SKILL.md + 承载初始化、设计依据、治理合同、协作/worktree、可选集成相同功能的全部 references（计划名为 initialization.md、design-principles.md、governance-contract.md、workflow-patterns.md、optional-integrations.md；合并或另拆时全部计入，不能通过改名排除）。新侧合计应低于 101,037 B；新增闭环应以去重和删除无增益论述抵偿，不用主入口变短掩盖整体膨胀。assets/references/eval-baseline.md 继续作为 L1/L1.5/L2/L3 定义、记分与回归记录的唯一账本，仅维护/评测时读取，不并入初始化常读范围；assets/pitch/presentation.html 保留为宣讲资产并同步核心概念，不进入执行路由。这两者在旧新两侧均不计入上述同功能执行指令字节集合，其自身变更量另报。

### 恢复与最小先行

初始化一开始就在目标既有 CURRENT/计划或出生档案位置写工作状态，而非完成后才追记。Small 用 docs/initialization.md；Medium/Large 用 docs/plans/active/initialization.md，验收后才归档到 completed 并置 done。初始化期间 CURRENT 仅留状态文件入口与下一步，不复制阶段或完成清单；同步修改 CURRENT.md.tpl 的 Small handoff 文案。Small 的 docs/initialization.md 是本次初始化唯一进度源，验收完成后在原路径置 status: done 并保留为出生档案，不新建归档目录、不迁往 plans，也不被普通任务覆盖。其后普通 Small 任务的当前状态仍由 CURRENT 承担；治理候选放审计清单的候选记录段，两类记录均不得写回出生档案。

状态至少能回答：已授权范围与 profile、来源版本、当前阶段、已完成/未完成产物、已核实事实及精确出处、旧约束迁移去向、重要取舍与未决冲突、下一步及须读材料、验收证据。阶段结束时覆盖当前状态或更新计划，不追加无限流水。先完成能安全接手的最小 AGENTS，再分模块处理大型项目文档；生成入口不得提前指向尚未生成的文件。

恢复时读 SKILL 入口、状态与当前阶段材料，核对现场差异；禁止为恢复而重读全部参考或仓库。拆文件本身不释放已读上下文，必要时通过新上下文接续。阶段粒度由任务和当前可用上下文决定，不硬编码“若干文件必为一阶段”。

### 治理、维护与演化

通用合同使用同一闭环：问题证据 → 最小候选 → 隔离验证 → 独立验收/保留任务回归 → 在既有授权内采用 → 观察与撤回。候选及结果使用项目实际存在的任务计划、bugfix 记录、审计清单或评测账本，不创建默认提案队列、独立进化目录或永久组织角色。Small 没有 plans、bugfix 或评测账本时，使用必备 docs/audit-checklist.md 的“改进候选与验证”记录段（位于“审计记录”之前），保存候选范围、基线、验收、结果与采用/撤回状态；CURRENT 只指向该记录，不另记一份候选状态。该段是现有清单中的按需记录，不提前建候选实体。

- 自维护：派生件重建与确定性修复可在授权范围内自动执行；年龄/频次只作线索，不要求无意义 touch。年龄线索沿用既有 maintain.py 记忆活性统计；未安装维护器的 Small 不为此另加年龄检查、提醒器或阻断项。
- 自治理：检查事实与规则是否一致；无法判定时保留证据与未决项，不能为消警编造结论。机械检查通过不等于语义正确。
- 自进化：改规则、模板、检查器或流程时记录候选适用范围、冻结基线/验收标准、保护场景、预期收益与副作用。独立视角与现有质量控制器复用，不规定固定部门、固定模型或永久协作拓扑。
- 基准标准可独立版本化改进；不得让被测候选在同一评价中决定自己的通过条件。保留任务不进入调参依据，成本与返工也参与比较。
- 明确本次预算、重试和停止条件；不通过的候选不晋升，证据不足不改写成“有效”。规则维护不能无限触发新的规则维护循环。
- 回滚声明区分文件与外部副作用；恢复文件不能撤销已部署、已删除的外部状态。需外部动作时按既有权限和单独验收处理。通用合同保持此中性措辞，不要求不存在的版本控制工具。
- 下游本地改进形成带复现、范围和结果的上游提案；不自动回写 Skill 来源，也不广播到其他项目。

自身 AGENTS.md 只包含维护工作流导航、源/副本边界、独立评审与检查入口。README 保留面向维护者的产品说明和评测方法，规范性条款向唯一合同归口；模板面向初始化后的项目，两者不互相加载整套说明。

### 文件治理与可选机制

Small 在 AGENTS 内联简短的 docs 存在/合并/创建/删除条件；Medium/Large 的详细规则只在 STRUCTURE 中，AGENTS 留指针。初始化步骤、模板注释与静态自检采用同一 profile 判定，Small 不再要求 STRUCTURE。audit-checklist 在 STRUCTURE 中使用 audit-checklist.md 相对链接；Small 从 AGENTS 直接导航。

按实际生成内容裁剪 audit-checklist 全文：Small 删除或改写 STRUCTURE 索引、overview 决策读取、memory/MEMORY/maintain 检查、plans/bugfix 等不存在资产的纯文本路径与操作指引；业务待办和改进候选改指项目实际存在的 CURRENT/本清单。不能只删除 Markdown 链接而保留无效命令或反引号路径，也不能再声明“模板无需裁剪”。Medium/Large 的可选文档同样仅在已生成时保留指引。

| 事实或规则 | Small 权威位置 | Medium/Large 权威位置 | 模板/入口引用方式 |
|---|---|---|---|
| 行为入口、命令绑定、完工入口 | AGENTS.md | AGENTS.md | 只引用实际存在的专题与命令 |
| docs 存在/合并/创建/删除条件 | AGENTS.md“文件治理”简短段 | docs/STRUCTURE.md“文件治理” | AGENTS 留指针；各模板注释按规模指向真实段落，不虚构 AGENTS 子节 |

检查全部模板中“治理规则/文件治理”的说明、链接和纯文本指针，使其遵守本表；CURRENT、MEMORY、plan、README、audit-checklist 等不能继续引用不存在的 AGENTS 段落。

现有独立评审、治理修改分级和评审标定边界须保留可发现；本仓本次按现有准则变更强度复查。生成项目不被迫复制本 Skill 自身的特定控制器制度；治理合同不自授免审或改阈值的权利。可选 hooks/插件的真实覆盖如实说明；不声称 pre-commit 不可绕过或“读入上下文即保证遵守”。

### 来源与升级

出生档案记录 source revision（Git 来源取已核实 commit；不可取得时如实 unknown）及本次采用的组件/模板标识。可机器复制的脚本保留来源哈希或组件清单；生成文档保留基线位置/哈希，完整基线置目标既有初始化记录旁或可检索版本提交中，不将源绝对路径写入 Git。

已有项目升级按“旧生成基线 / 项目当前版本 / 新源组件”三方比较；用户定制不能由新模板覆盖。基线不可取时禁止假装可自动合并，按当前规则重新调查并给出差异化迁移。此轮实现文档与数据合同及一个代表性迁移验证，不开发批量自动更新器。新来源修订不自动使所有下游改变运行规则。

## 验收合同

### A. 有界上下文与契约保真

- SKILL 主文件满足上述行数/字节预算；按需参考没有反向要求开工全读。字节报告列出上文固定集合每个文件的路径与字节数，并按 Small、Medium/Large、可选集成和恢复阶段列出实际要求读取的文件/分区；总量是静态维护范围，分阶段读取量另报，均不将字节数冒充 token。
- 将原文有行为影响的不变量列成迁移核对表：保留、去重到哪里、因本次用户决断明确调整哪项；无不可解释丢失。
- 四 profile 均有独立、保留的实物目录并运行机械合同验证；Small + no-Git、Medium + Git 两套由独立执行 Agent 按新 Skill 实际初始化，另两套为使用相同模板条件投影的合成 fixture。报告逐套注明生成方式、输入和产物位置；两套 Agent 执行属于新版本 pilot，不是旧新版本 A/B。Large 另做分阶段中断/恢复试验，KB 运行既有迁移布局测试。
- 恢复试验由新上下文只接收入口、目标路径和已写状态，能定位下一步并保留旧约束；未完成阶段不报初始化完成。

### B. 行为回归与产物检查

- 测试检查主入口路由、profile 裁剪、治理合同与来源/恢复信息的可达性；原先将全部短语固定到 SKILL 的断言调整为实际合同，不能简单删掉失败测试或把全部 references 拼接后继续 assertIn 来掩盖入口边界。
- Small 审计清单投影测试检查纯文本指令、反引号路径和命令，不含不存在的 STRUCTURE/overview/memory/plans/maintain 指引；治理合同及其最终 docs/governance.md 纳入 no-Git 投影检查，neutral 合同也必须接受此回归。新增 governance.md 在 Medium/Large 导航与 STRUCTURE 中可达，Small 既不生成它也不留指针。
- 增加 check_all 行数/结构的真实失败与成功场景，覆盖普通布局和 .meta/scripts 布局；修复后从仓库根运行默认收集命令 `python -X utf8 -m pytest tests/ -q` 必须成功。修复现有 tests 包导入冲突，不能仅用 --import-mode=importlib 替代默认命令验收；UTF-8 子进程设置按实际环境保留。
- 生成产物运行 changelog titles/add、audit check、check_all、维护器（按 profile），无死链、指导注释和未填占位符；Small 不建 STRUCTURE/plans/memory/maintain，no-Git 不出现或执行 Git-only 行为。
- 对已有 instruction 的代表性迁移验证：硬约束保留，真实 manifest/CI 命令优先，用户定制不被新模板吞掉。
- 三方升级样例证明本地定制保留、模板改动可辨认、无基线时诚实降级；不要求新增自动更新脚本。

### C. 自治理与证据边界

- 源码自用 AGENTS 与下游最小合同均能回答如何维护、何时提候选、按何标准验收、何时停止与恢复；不依赖已卸载/未安装的全局 Skill。
- 改进候选不能自己更改通过标准、抹去失败样本或把执行者自检冒充独立验收。既有授权内工作不重复确认，预算上限不因“自治”扩大。

## 风险与止损

- 拆分容易制造多跳与重复：入口用明确触发路由，去重后再测总体指令量，不以文件数或行数作为质量替身。
- 规则自指容易无穷递归：一次候选固定基线与边界，采用后再观察；不满足预算/权限/证据则停止该候选，不偷偷扩权。
- 生成流程仍含语义填写：机械通过不保证项目画像正确；依赖独立冷启动任务和真实迁移验收。
- 多宿主副本可能陈旧：源码改造验收与 cc-switch 发布/部署验收分开；不得手改副本补齐表面一致。
