把仓库变成 Agent 可持续协作的知识系统

三条贯穿全系统的原则

1. 给地图，不给百科

AGENTS.md 始终驻留在上下文，只承载规则、导航与完工清单。

建议控制在 200 行 / 400 词以内。

2. 事实源有优先级

可执行事实源优先：CI、hook、task runner、manifest 与配置，高于 README 和旧文档。

3. 验证需要新视角

治理文档与高风险改动必须由独立视角复查；执行完成不等于验证完成。

渐进式披露：从入口到经验

AGENTS.md行为规则、导航、内联记忆（始终驻留）
docs/STRUCTURE.md文档总索引（一张导航表）
docs/*.md设计原因、部署约定、环境陷阱
docs/plans/跨会话与多 Agent 的交接协议
.agents/memory/MEMORY.md经验类知识的统一检索入口
docs/CHANGELOG.md脚本化维护的变更摘要

文档维护：记录原因，不复制事实

应该记录

  • 设计原因：为什么这样选
  • 协作约束：代码看不到的约定
  • 环境陷阱：已验证的坑与解法
  • 外部约定：部署与基础设施边界

通常不重复

  • 目录与签名：代码可直接读取
  • Git 历史：交给 git log / blame
  • 派生索引：交给脚本重建
  • 迁移考古：不污染当前信息空间

Occam 防止治理系统自增殖；Bitter Lesson 反对封顶型先验，但保留防呆型机制。

计划：跨上下文的可执行交接

计划文件不是待办清单，而是“失忆”后的恢复协议。
  • 目标与阶段：当前该做什么、完成标准是什么
  • 状态与责任：queue → claimed → in_progress → review → completed
  • 交接摘要：已改文件、验证结果、偏离与遗留
  • 合理粒度：经验上每阶段修改 5–10 个文件，并保持可运行

按任务复杂度选择工作模式

模式适用场景最低要求
直接执行小修改、低风险、单会话AGENTS + docs/CURRENT.md
分阶段中等复杂度、可能跨会话上述 + docs/plans/active/
协作模式高风险、多 Agent 并行任务分配 + reviewer + worktree 隔离
协作倾向项目可选安装 worktree_task.py：create / check / integrate / cleanup 四动作，canonical 分支仅允许快进。

小型 / 中型 / 大型：先裁剪，再生成

规模核心产物计划与记忆
小型AGENTS + README + CURRENT + CHANGELOG不建 plans，不建 memory
中型全套 docs/ + 维护脚本plans + .agents/memory/
大型中型全套 + 模块级拆分模块子计划 + 统一记忆入口
规模必须由用户确认；默认从轻量开始，不为“完整感”预付复杂度。

中型项目的目标结构

目标项目/
├── AGENTS.md
├── CLAUDE.md / GEMINI.md        # copy 同步（默认）
├── README.md
├── .agents/memory/
│   ├── MEMORY.md                # 统一经验索引
│   └── user/role.md
├── docs/
│   ├── STRUCTURE.md / CHANGELOG.md / CURRENT.md
│   ├── overview.md / deployment.md / audit-checklist.md
│   ├── plans/{active,completed}/
│   └── problems/bugfix/         # Bugfix 经验档案
└── scripts/
    ├── agent_links.py / changelog.py / audit.py
    └── maintain.py              # 中型+统一维护入口

软约束写文档，硬约束交给工具

操作前同步

git fetch origin，确认工作区、分支与 ahead/behind。

三入口同步

agent_links.py 执行 copy 同步（默认），hook 防止内容分叉。

日志轻量写入

changelog.py 提供 titles / show / recent / add，不读全文。

机械审计

audit.py 检查死链、结构、漂移、出生档案与记忆完整性。

统一维护

scripts/maintain.py 重建索引并串联 audit 与同步检查。

独立复查

治理文档按性质分级 review，规则变化必要时走 converge。

记忆系统：一个入口，持续维护

经验检索不落到统一入口，就等于对未来 Agent 不存在。

.agents/memory/MEMORY.md

索引标记段由 scripts/maintain.py 自动重建；Agent 负责经验内容的取舍，不手工维护派生目录。

docs/problems/bugfix/

Bugfix 文档进入同一索引，并记录 liveness、last_confirmed、confirmed_count；命中并采用后再 touch。

当前体系重点防止的六类漂移

巨型 AGENTS

入口挤占上下文；把专题内容下沉到 docs/。

文档复制代码事实

同一事实出现多份，修改后必然腐烂。

CURRENT 与 plans 空转

按项目规模裁剪，不创建永远没人维护的空壳。

共享工作树并行

多个 owner 争用 index；协作时使用 worktree 隔离。

手工维护派生索引

让 maintain.py 重建 MEMORY 索引与 Bugfix 分区。

实现完成即宣告完成

保留 review 节点，以独立视角验证高风险改动。

仓库是协作的唯一事实源

让规则可见、知识可找、状态可交接、漂移可检测。
