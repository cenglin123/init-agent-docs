# 项目治理合同

本合同服从项目既有领域规则、授权与质量控制器；实际入口、记录位置与命令由项目 AGENTS 绑定。无需特定目录、版本控制工具、外部 Skill、API 或常驻服务。

## 日常维护

派生件重建和确定性修复可在既有授权内执行，以适用测试与现有独立评审等级验证。年龄、频次只作调查线索，不为消警做无意义 touch；不把机械通过当成语义正确。无法判定哪侧错时保留事实、出处和未决项，不编造结论。

## 规则改进

改变行为、约束、模板、检查判据或流程时，使用项目已有任务记录或审计清单记录候选，不预建队列或组织：问题证据 → 最小候选 → 隔离验证 → 独立验收/保留任务回归 → 既有授权内采用 → 观察与撤回。

冻结候选适用范围、基线和验收标准，记录保护场景、预期收益与副作用；比较实际成本与返工。保留任务不进入调参依据。基准可以另行版本化改进，但被测候选不能在同一评价里更改自己的通过条件、抹去失败样本或自证成功。

复用项目现有质量流程；普通项目规则修改默认一次独立视角审查，遵从项目已有更严格要求。独立视角不能由执行者自检替代，不固定部门、模型或永久拓扑。债务/审计记录及候选状态、证据、验证、拒绝、观察等纯记录编辑豁免；改变行为或判据仍须复查。已有授权不重复申请，自维护不授予改规则权限，预算不因自治扩大。

本次工作明确预算、重试和停止条件；失败候选不晋升，证据不足保持未证实，规则维护不得无限触发自身。记录采用或拒绝的证据及观察、撤回条件。

回滚声明区分文件与外部副作用：恢复文件不能撤销已部署、已删除的外部状态；外部动作按既有权限与单独验收处理。

下游改进只形成带复现、适用范围和结果的上游提案，不自动回写来源或广播其他项目。
